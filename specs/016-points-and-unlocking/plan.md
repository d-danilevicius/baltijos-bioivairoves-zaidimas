# Implementation Plan: Points and group unlocking

**Feature:** `specs/016-points-and-unlocking/spec.md`
**Branch:** `016-points-and-unlocking`
**Status:** draft
**Depends on features:** 003-access-control, 012-student-task-list, 013-observation-card, 014-task-completion

## Summary

When a student submits an answer, the server compares it with the correct answer of the task, saves the points (10, 20 or 30 by the difficulty group, or 0) together with the submission, and returns the points, the correct answer and, when this submission unlocked the next group, its number. The unlocking rule of VT-014 (60 % of the maximum points of the previous group) replaces the old rule of feature 012 and has one implementation that the task list, the task opening and the submission use. The task list shows the points of done tasks and groups; the result screen (E07) shows the points, the correct answer, the submitted data, the unlock message and the buttons “Kita užduotis” and “Į užduočių sąrašą”. Repeating a task, the results page and photos belong to features 015, 017 and 018.

## Technical Context

- **Language and version:** C# with .NET 10 (server); TypeScript (frontend).
- **Libraries:** as selected in `docs/architecture.md` (section 1). No new library. The additions to the responses are single fields written in the existing mapping methods; AutoMapper is not added.
- **Frontend:** React with Vite, React Router and Tailwind CSS. No new library.
- **Storage:** PostgreSQL through Entity Framework Core; one new column `Points` in `Submissions`; migration `AddSubmissionPoints`.
- **Testing:** xUnit (unit and integration, PostgreSQL in Testcontainers), Vitest and React Testing Library.
- **Target platform:** web application in current Chrome, Firefox, Edge and Safari; screens from 360 px width.
- **Constraints:** HTTPS only; POST uses the existing CSRF protection; no secret is stored in the repository.

## Structure and Main Components

- Server:
  - `Entities/ClassTask.cs` – two small members: the static `PointsOfGroup(group)` (10 × group, the only place of VT-016) and `PointsFor(answer)` (the task decides: the full points when the answer matches `CorrectAnswer` ignoring letter case and spaces at the beginning and the end, otherwise 0). The maximum points of a task are `PointsOfGroup(DifficultyGroup)`.
  - `Entities/Submission.cs` – a new property `Points` (set by the server).
  - `Migrations/…_AddSubmissionPoints.cs` – adds the column `Points` (not null, default 0), generated by EF Core.
  - `Services/StudentProgress.cs` – replaces `TaskGroupUnlocking`. It is created from the tasks of the class (identifier and group) and the points of the student per task, and answers: the points and the maximum points of a group, `IsUnlocked(group)` (group 1 always; a group after an empty group always; otherwise the points of the previous group × 100 ≥ 60 × its maximum, whole numbers), and `GroupUnlockedBy(taskId, points)`, the group that a new submission of that task with these points unlocks (empty when it unlocks none). One rule for FR-042 and FR-005.
  - `Services/StudentTaskAccess.cs` – the unlock check uses `StudentProgress` instead of the list of groups with tasks (it reads the identifiers and groups of the class tasks and the student’s points).
  - `Services/StudentTaskService.cs` – builds the groups with `StudentProgress`: the points of done tasks, the points and the maximum points of each group; `Done`, `Locked` and “Tęsti” as before.
  - `Services/StudentTaskDetailsService.cs` – returns the student’s submission with the correct answer of the task (the correct answer exists only inside the submission).
  - `Services/SubmissionService.cs` – after the access and the checks of feature 014 it calculates the points with `ClassTask.PointsFor`, saves them in the same `SaveChanges` as the answer, and takes the unlocked group from `StudentProgress` (before and after).
  - `Services/SubmissionExtensions.cs` – `ToResponse()` also gets the points, the correct answer and the unlocked group.
  - `DTOs/Responses/SubmissionResponse.cs` – new properties `Points`, `CorrectAnswer` and `UnlockedGroup` (a whole number or empty; set only in the response of the POST).
  - `DTOs/Responses/StudentTaskResponse.cs` – a new property `Points` (empty until the task is done).
  - `DTOs/Responses/StudentTaskGroupResponse.cs` – new properties `Points` and `MaxPoints`.
  - `DTOs/Responses/StudentTaskDetailsResponse.cs` – only the comment changes: the correct answer is never sent before the student submits the task.
  - `Controllers/StudentSubmissionController.cs` – no change of the routes or the statuses.
- Frontend:
  - `types/submission.ts` – `points`, `correctAnswer`, `unlockedGroup`; `types/studentTask.ts` – `points` of a task, `points` and `maxPoints` of a group.
  - `helpers/submissionMessage.ts` – the texts of E07: „Gavote N taškų.“, the label of the correct answer, „Atrakinta N sudėtingumo grupė.“, “Kita užduotis”, “Į užduočių sąrašą”.
  - `helpers/studentTaskMessage.ts` – the text of the points in the list („10 tšk.“, „30 iš 50“).
  - `hooks/useNextTaskId.ts` – after the result is shown, reads `GET /api/my/tasks` (existing `getMyTasks`) and returns `continueTaskId` (empty when there is no other task or the call fails).
  - `components/submissionResult.tsx` – E07: the points, the correct answer, the submitted data with the label, the unlock message and the two buttons (“Kita užduotis” only when `useNextTaskId` returns a task).
  - `components/studentTaskGroup.tsx` – the points of the group and of each done task as text.
  - `pages/StudentTaskPage.tsx` – no new logic (the result component receives the submission as before).

## Server Request Changes

- `POST /api/my/tasks/{taskId}/submissions` – the 201 response has `points`, `correctAnswer` and `unlockedGroup`; the statuses and the access are unchanged (201, 400, 401, 403, 404, 409).
- `GET /api/my/tasks/{id}` – the `submission` has `points` and `correctAnswer`; a task without a submission has no correct answer.
- `GET /api/my/tasks` – each done task has `points`; each group has `points` and `maxPoints`; `isUnlocked` is calculated by VT-014.

## Data Model Changes

- New column `Submissions.Points` (integer, not null, default 0); migration `AddSubmissionPoints` in the same branch. Submissions saved before the migration get 0 (only test databases have them). No new table and no stored “unlocked” flag.

## Testing Plan

- Unit tests (`ClassTask`): 10, 20 and 30 points for a correct answer in groups 1, 2 and 3; 0 points for an incorrect one; letter case and outer spaces are ignored; inner spaces are kept (a different answer); „7“ is correct for 7 and „07“ is not.
- Unit tests (`StudentProgress`): group 1 is unlocked without points; exactly 60 % unlocks (3 of 5 tasks’ points) and 59 % does not; group 3 depends on group 2; a group after an empty group is unlocked; a deleted task does not count (its points and its maximum are gone); `GroupUnlockedBy` reports the unlocked group only when the submission crosses the threshold; no group is reported for a submission in the last group or after the group is already unlocked; the maximum changes when a task is added.
- Unit tests (`SubmissionService`): the points 10/20/30 and 0 are saved with the answer; `UnlockedGroup` is set when the submission reaches 60 % and is empty otherwise; the checks of feature 014 (locked, other class, second submission, wrong option) save nothing and no points.
- Unit tests (`StudentTaskService`): done tasks have points; a group has the sum and the maximum; a locked group becomes unlocked by points; an empty previous group does not lock the next one; the points of another student are not used.
- Unit tests (`StudentTaskDetailsService`): the correct answer is in the submission only; a task without a submission has none.
- Integration tests: a correct answer gives 201 with 10, 20 or 30 points and the correct answer; an incorrect answer gives 0; the points are already in the database when the response is returned and are the same after a new login; the time of the POST is measured and is below 1 second (NFR-015); after enough points `GET /api/my/tasks` shows the next group unlocked and the POST returned its number; below 60 % it stays locked; the correct answer is absent in `GET /api/my/tasks/{id}` before the submission and present after it; two students have separate points; a teacher and an administrator get 403, a visitor 401 on the three student endpoints (the existing tests are kept).
- Frontend tests: E07 shows the points, the correct answer, the submitted data with the label and the unlock message only when the number comes; “Kita užduotis” opens the next task and is not shown when there is none or the call fails; “Į užduočių sąrašą” opens the list; a reopened submitted task shows the saved points; E04 shows the points of done tasks and groups as text („30 iš 50“) and the locked message.

## Technical Notes

- The server decides the correctness and the points; the request is not changed and has no field for them.
- The points are saved in the same database operation as the answer, so they are saved even if the connection is lost after the request has reached the server (NFR-018). Nothing else is written after the save.
- The unlocking is calculated from the current tasks and submissions each time and is not stored; when the teacher adds or deletes a task, the maximum changes and a group may lock or unlock on the next call (Edge Cases of the specification).
- Only the group after the group of the submitted task can change its unlocked state, so the response of the POST needs one comparison of the progress before and after the new points, without another query.
- The old class `TaskGroupUnlocking` and its tests are replaced by `StudentProgress` and its tests; no other rule about locking remains.
- The task list is not paged and has few tasks (up to 9 GBIF tasks and the teacher’s tasks), so reading the identifiers and the points of one class is cheap.
- E07 still has no address; “Kita užduotis” uses the same “Tęsti” rule as the list (`continueTaskId`), so no new endpoint is added.
- The group points are shown as numbers (for example „30 iš 50“); the status is also written in words (`docs/ux.md`, accessibility).
